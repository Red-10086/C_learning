# 2026-05-09 教训：别让大模型碰字节,大模型不可做逐字节任务.

## 今天发生了什么
引进版日文 C 教材的配套源码文件仍是 **Shift_JIS 编码**，在中文环境下打开全是乱码。  
任务很简单：把几百个 `.c` 文件从 Shift_JIS 转成 UTF-8，再把里面的日文注释翻译成中文，最后写回原文件。

## 我最初的"聪明"方案
想绕过自己不熟悉的 `iconv`/`Python` 脚本，直接让**本地 AI Agent 大包干**：
1. 逐字节读取原始 `.c` 文件
2. 把 Shift_JIS 转码成 UTF-8
3. 翻译日文注释为中文
4. 覆盖写回原文件

## 为什么这个方案是死路（核心推理）
与 AI 的对话让我意识到：**大模型根本做不了"逐字节保真"的任务。**

### 证据链
- **URL 编码实验**：让模型把"亿万同人"做 UTF-8 编码，结果得到的是"一万同人"。模型不是查表转字节，而是凭概率"猜"下一个最像的 token。
- **文本复制实验**：一个 `cp` 命令复制 1MB 文件一万次也不会错；让大模型"逐字搬运"，第一遍就可能近义词替换、丢换行、改标点。
- **魔法数字**：模型写代码时把起征点 `5000` 写成 `3000`，程序能编译、能运行、测试也可能通过，但**静静地算错账**。

### 根本原因：两种媒介
| | 脚本/程序 | 大模型 |
|---|---|---|
| **本质** | 符号执行器（查表、跳转、校验） | 概率生成器（猜下一个最可能的 token） |
| **存储** | 逻辑与数据分离，可精确修改某一行 | 逻辑融在千亿权重里，分布式纠缠 |
| **错误特征** | 错了就崩溃/报错，立刻暴露 | **静默漂移**，输出看起来完美，内容已偷梁换柱 |
| **适用域** | 编码转换、文件复制、数值计算、协议实现 | 语义理解、创意生成、逻辑框架、解释说明 |

**规范世界**（文件编码、RFC 标准、税法阈值）是离散的、非此即彼的；**经验世界**（翻译、理解、联想）是连续的、概率的。让大模型直接操作 Shift_JIS 字节流，等于让水彩画师画工程图纸。

## 给未来的我的行动指南
1. **转码、哈希、文件覆盖、常量写入** → 绝对不用大模型，用 `iconv`、`Python`、`sha256sum`、`rsync`。
2. **翻译注释** → 可以等大模型做，但必须是**在已转好的 UTF-8 文本上**辅助翻译，且人工核对关键术语；绝不让模型直接"读-转-写"闭环操作原文件。
3. **看到"用 AI 自动化一切"的冲动时** → 先问自己：这个任务如果错了，是报错还是静默？如果是静默，退回到脚本。

## 一句话总结
&gt; 概率引擎负责"大概对"，确定性工具负责"绝对对"。两者边界不可混淆。
