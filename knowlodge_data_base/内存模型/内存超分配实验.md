# 内存超分配实验：索引与引言

> **核心发现**：通过控制数据熵（可压缩 vs 不可压缩），可以迫使操作系统暴露其内存管理的真实分层策略——从"内存压缩"切换到"磁盘交换"。

---

## 一、实验设计

**控制变量**：`malloc(100MB)` 循环申请，每次写入 `long long` 数组，但改变**随机数填充位数**。

| 轮次 | 数据特征 | 预期 |
| :--- | :--- | :--- |
| **第一轮** | `rand()` 15位随机，49位为 `0` | 高可压缩 |
| **第二轮** | 4次 `rand()` 移位拼接，60位随机 | 接近不可压缩 |

---

## 二、对照结果

| 指标 | 第一轮（可压缩） | 第二轮（不可压缩） |
| :--- | :--- | :--- |
| **崩溃极限** | ~165 GB | ~157 GB |
| **64GB后内存申请速度** | 维持 ~300MB/s | 暴跌至 ~100MB/s |
| **磁盘写入** | 几乎无动静 | 大量写入，可用空间缩水 88GB |
| **RAM 占用特征** | 平稳增长 | 周期性"写入峰"后骤降 |
| **主导机制** | **内存压缩**（Memory Compression） | **磁盘交换**（Paging / Swap） |

---

## 三、关键现象映射

| 观察 | 机制 | 结论 |
| :--- | :--- | :--- |
| 165GB > 64GB 物理内存，磁盘不动 | 操作系统识别全零/相似页，进行**内存内压缩** | 虚拟内存承诺 + 压缩 = 超分配幻觉 |
| 80GB 后申请速度腰斩 | 物理页框耗尽，开始**逐页换出**到 NVMe | 性能断崖 = 从 RAM 降级到磁盘 |
| "数GB/s 写入峰" + RAM 应声回落 | Windows **工作集批量裁剪** | 冷页被批量打入 `pagefile.sys` |
| 实验后磁盘空间未回收 | 页面文件**惰性收缩**（防止反复分配开销） | 交换文件是持久占位，非临时缓冲 |
| 157GB ≈ 64GB RAM + 93GB 页面文件 | **提交限制**（Commit Limit）到达 | 虚拟地址空间受限于 RAM + 页面文件总和 |

---

## 四、工程启示

1. **`malloc` 分配的是虚拟地址，不是物理内存**——操作系统用"空头支票"允许超分配。
2. **数据模式决定内存成本**——全零/可压缩数据几乎"免费"，高熵数据1:1消耗物理页框。
3. **性能断崖点在物理内存边界**——64GB 不是容量极限，是**性能极限**。
4. **页面文件是物理现实**——当压缩被打穿，NVMe 就是你的 RAM，延迟高 3 个数量级。
